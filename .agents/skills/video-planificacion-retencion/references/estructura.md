# Estructura, ritmo y paso a producción

Reutiliza las familias narrativas de [youtube-scriptwriting](../../../../Biblioteca_Planificacion/Fuentes_Comunidad/cdeistopened/skills/youtube-scriptwriting/references/structures.md) y las propuestas de [long-form-youtube](../../../../Biblioteca_Planificacion/Fuentes_Comunidad/yaxeen/skills/long-form-youtube/SKILL.md). La selección siguiente las adapta al trabajo con recursos reales y a distintos formatos.

## Elegir una estructura por la promesa

| Promesa | Estructura de partida | Qué debe avanzar |
| --- | --- | --- |
| Entender una función | Resultado → acción → explicación → comprobación | Relación entre lo que hace el usuario y lo que ocurre |
| Aprender una tarea | Meta → requisitos → pasos → prueba → errores frecuentes | El espectador puede reproducir el proceso |
| Resolver un problema | Situación → fricción → opción → demostración → límite | Un problema definido obtiene una respuesta |
| Contar una experiencia | Situación → obstáculo → decisión → consecuencia | Hay causalidad, no una sucesión de hechos sin relación |
| Comparar opciones | Criterio → condiciones → pruebas → diferencias → elección | El criterio permite interpretar cada resultado |
| Explicar un caso | Resultado → contexto → proceso → evidencia → lección | Distinguir lo observado de lo que creemos que lo produjo |
| Dar una lista | Promesa → elementos autónomos con ejemplos → síntesis | Cada elemento añade algo distinto |
| Hacer humor | Situación → expectativa → ruptura → remate | El público entiende la relación; el chiste no depende de texto ilegible |
| Presentar una novedad | Qué cambia → a quién afecta → demostración → disponibilidad | Separar lo publicado de lo anunciado o previsto |

No encajes todas las piezas en conflicto dramático. Una respuesta útil puede interesar por claridad, demostración o belleza del movimiento.

## Progresión que entrega valor

Cada bloque debe responder una pregunta, mostrar una prueba, hacer avanzar la acción o producir un efecto narrativo intencional. Una pregunta nueva puede mantener interés, pero las respuestas parciales también recompensan. En un guion largo, registra qué sabe el espectador al salir de cada capítulo.

Usa relaciones de causa y consecuencia cuando existan: **ocurre esto → plantea este problema → se decide esto → cambia esto**. No inventes obstáculos o fracasos para hacer que una demo parezca una historia.

## Ritmo: decisiones observables

- Elimina esperas que no aporten información, pero conserva el tiempo necesario para leer, reconocer una interfaz o entender una operación.
- Cambia plano, encuadre, gráfico o sonido para orientar la atención. Evita que un efecto tape el dato que intenta destacar.
- Alterna explicación con prueba, plano general con detalle y densidad con respiración cuando el contenido lo pida. El silencio también puede tener intención.
- Una aceleración cambia la percepción del proceso: si interesa su duración real, déjala clara. No hagas pasar un montaje por una demostración continua sin que se entienda.
- Mide la voz antes de fijar la duración de sus escenas. Lee el texto con el tono previsto; una estimación de palabras por minuto sirve para presupuestar, no reemplaza la locución.
- Evita que un cierre largo anuncie que ya terminó todo mientras aún queda información importante.

## Título, miniatura y apertura

Para YouTube largo, diseña el conjunto antes de desarrollar todo el guion: una promesa, varias parejas posibles y una recomendación. La miniatura puede mostrar y el título concretar. La primera escena debe corresponder con lo que motivó el clic.

No impongas número de palabras, cara exagerada o flecha a toda miniatura. Comprueba legibilidad pequeña y claridad. Si los recursos no contienen el resultado prometido, cambia el concepto o pide la prueba que falta. La biblioteca original de [títulos y miniaturas](../../../../Biblioteca_Planificacion/Fuentes_Comunidad/yaxeen/skills/titles-and-thumbnails/SKILL.md) ofrece variantes para adaptar.

En piezas de feed, el primer fotograma y el texto en pantalla hacen un trabajo distinto al de una miniatura de exploración. No traslades mecánicamente la fórmula de clic a una pieza que el usuario ya ve reproduciéndose.

## Plan de recursos antes de generarlos

| Estado | Qué registrar |
| --- | --- |
| Existe y está revisado | Ruta exacta, fragmento útil y cualquier límite de encuadre o sonido |
| Existe, falta revisar | Qué hay que inspeccionar antes de decidir |
| Grabar | Acción, plano, duración estimada y datos que deben verse |
| Crear o animar | Función de esa escena, texto o elementos y lugar en el montaje |
| Conseguir | Tipo de recurso y sustituto posible si no está disponible |

Para una grabación pendiente, entrega una instrucción concreta: qué se hace, qué debe quedar visible y cuándo empezar o terminar. No una lista genérica de «B-roll atractivo».

La biblioteca compartida está en `01_Proyectos/Recursos videos/README_RECURSOS.md`, relativa a Videos_Rapidos. Para efectos, consulta la categoría que necesites en vez de leer todos los nombres. Para Tony Stark, usa el índice visual y sus descripciones; algunas variantes de baile empiezan con otro plano.

## Plan mínimo que recibe la edición

1. Propósito, formato, duración objetivo y qué se conserva.
2. Apertura elegida y promesa que cumple.
3. Tabla de escenas con tiempos estimados, visual, voz, texto, sonido y recurso.
4. Elementos pendientes de grabar o crear, con prioridad.
5. Qué se quiere revisar en la primera versión.

Guarda decisiones reutilizables en el perfil y decisiones propias de la pieza en su ficha. Si el usuario pide ejecución, pasa a [remotion-produccion](../../remotion-produccion/SKILL.md); la planificación no obliga a una ronda adicional de aprobación.
